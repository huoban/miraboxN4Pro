# StreamDock 插件机制逆向总结（客户端 3.10.x 基线）

> 来源：`C:\Program Files (x86)\StreamDock\StreamDock.exe` 静态逆向 + 官方 SDK 文档 + `MiraboxSpace/StreamDock-Plugin-SDK`、`StreamDock-Plugins` 仓库。
> 用途：后续在 n4pro-core 中复刻插件加载与执行能力。标注「推断」的条目尚无真机抓包证实。

---

## 1. 生态与兼容性

- StreamDock 插件协议**兼容 Elgato Stream Deck**：客户端同时存在 `connectMiraBoxSDSocket(...)` 与 `connectElgatoStreamDeckSocket(...)` 两个连接入口（0x2940F18 附近）。
- SDK 版本：manifest 中 `SDKVersion: 3`，最低软件版本由 `Software.MinimumVersion` 声明（示例 `3.10.188.226`）。
- 插件以**独立进程**运行，与客户端通过 **WebSocket + JSON** 通信；语言无关（官方模板：JS / Node / Vue / C++ / Qt / Python）。

---

## 2. 插件安装位置与注册

| 项目 | 值 |
|---|---|
| 插件目录 | `%APPDATA%\HotSpot\StreamDock\plugins\` |
| 插件单元 | `<UUID>.sdPlugin` 文件夹（如 `com.mirabox.streamdock.demo.sdPlugin`） |
| 注册表 | `HKEY_CURRENT_USER\Software\HotSpot\StreamDock\<UUID>`（安装/卸载状态） |
| 生效方式 | 首次放入后**需重启客户端**；之后可热重载 |
| 调试页 | `http://localhost:23519/`（浏览器可查看插件列表并重载） |

插件目录内同时存在官方内置插件（`com.hotspot.streamdock.*`）与第三方插件（`com.mirabox.streamdock.*`）。

## 3. manifest.json 完整字段

实测示例（SDK 仓库 V2 Node 模板）：

```json
{
  "Actions": [{
    "Icon": "static/App-logo.png",
    "Name": "demo",
    "DisableAutomaticStates": true,
    "States": [{ "Image": "static/App-logo.png", "TitleAlignment": "center", "FontSize": "8" }],
    "Settings": { "titleFormat": "title-artist", "showTitle": true },
    "Controllers": [],
    "UserTitleEnabled": true,
    "SupportedInMultiActions": true,
    "Tooltip": "demo operation",
    "UUID": "com.mirabox.streamdock.demo.demo",
    "PropertyInspectorPath": "propertyInspector/demo/index.html"
  }],
  "SDKVersion": 3,
  "Author": "MiraBox",
  "Name": "demo",
  "Icon": "static/App-logo.png",
  "CodePathWin": "plugin/index.js",
  "CodePathMac": "plugin/index.js",
  "Description": "demo operation",
  "Category": "demo",
  "CategoryIcon": "static/App-logo.png",
  "Version": "1.0.0",
  "URL": "https://mirabox.key123.vip/home",
  "OS": [{ "Platform": "mac", "MinimumVersion": "10.11" }, { "Platform": "windows", "MinimumVersion": "7" }],
  "Software": { "MinimumVersion": "3.10.188.226" },
  "Nodejs": { "Version": "20" }
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `Actions[]` | 插件提供的动作列表 |
| `Actions[].UUID` | 动作唯一 ID，配置文件中引用 |
| `Actions[].Icon` | 动作列表图标 |
| `Actions[].States[]` | 多状态外观（Image/TitleAlignment/FontSize…） |
| `Actions[].Settings` | 默认设置（写入 profile 的 Settings） |
| `Actions[].Controllers` | 适用控制器（Keypad / Encoder），空数组=默认 Keypad |
| `Actions[].SupportedInMultiActions` | 是否可放入多动作 |
| `Actions[].PropertyInspectorPath` | 属性检查器 HTML 路径 |
| `Actions[].DisableAutomaticStates` / `UserTitleEnabled` | 自动状态切换 / 用户自定义标题 |
| `CodePath` / `CodePathWin` / `CodePathMac` | 插件入口（JS/可执行文件） |
| `Category` / `CategoryIcon` | 动作面板分类 |
| `Software.MinimumVersion` | 兼容的客户端最低版本 |
| `Nodejs.Version` | 内置 Node 运行时版本（如 20） |
| `Profiles` / `Readonly` / `DontAutoSwitchWhenInstalled` / `DefaultWindowSize` | 插件自带场景、只读、安装时不自动切换、PI 窗口尺寸 |
| `MultiActionImage` / `Title` / `Author` / `URL` / `SDKVersion` / `OS` | 元信息 |

## 4. 插件进程启动规则

客户端启动插件时的命令行（0x2940FC9 附近实测字符串）：

```
node <CodePathWin> -port <port> -pluginUUID <uuid> -registerEvent <event> -info <json>
```

| 参数 | 含义 |
|---|---|
| `-port` | 客户端 WebSocket 服务端口（每个插件会话分配） |
| `-pluginUUID` | 插件实例 UUID（manifest 的插件 ID） |
| `-registerEvent` | 注册事件名，插件为 `registerPlugin`，属性检查器为 `registerPropertyInspector` |
| `-info` | JSON：应用/设备/插件信息（含 `application`、`devices`、`plugin` 字段，兼容 StreamDeck 格式） |

规则：

- `CodePathWin` 为 `.js` 时用内置 `node` 启动；为 `.exe` 时直接执行；
- `RunAsAdministrator` 支持提权启动（推断：manifest 可选字段）；
- 插件进程退出后客户端会提示重启插件（`Plugin %1 %2 is now connected` 日志）；
- 客户端内置 Node 运行时（`node` 位于安装目录）。

## 5. WebSocket 通信协议

### 5.1 连接与注册

插件启动后连接 `ws://127.0.0.1:<port>`（端口由 `-port` 传入），发送注册消息：

```json
{ "event": "registerPlugin", "uuid": "<pluginUUID>" }
```

属性检查器连接同一端口，发送：

```json
{ "event": "registerPropertyInspector", "uuid": "<pluginUUID>" }
```

### 5.2 客户端 → 插件（事件）

| 事件 | 方向/时机 |
|---|---|
| `keyDown` | 按键按下（含 `action`、`context`、`device`、`payload.settings`、`payload.coordinates`） |
| `keyUp` | 按键抬起 |
| `dialRotate` | 旋钮旋转（推断：`ticks`、`pressed`） |
| `dialDown` / `dialUp` | 旋钮按下/抬起（推断） |
| `touchTap` | 触控条点击（推断） |
| `willAppear` | 动作出现在画布 |
| `willDisappear` | 动作从画布移除 |
| `didReceiveSettings` | 设置变更回传 |
| `didReceiveGlobalSettings` | 全局设置回传 |
| `propertyInspectorDidAppear` / `propertyInspectorDidDisappear` | PI 打开/关闭 |
| `deviceDidConnect` / `deviceDidDisconnect` | 设备接入/断开 |
| `applicationDidLaunch` / `applicationDidTerminate` | 应用启动/退出 |
| `systemDidWakeUp` | 系统唤醒（推断） |
| `sendToPlugin` | 仅 PI → 插件（客户端转发） |

### 5.3 插件 → 客户端（指令）

| 指令 | 作用 |
|---|---|
| `setImage` | 设置键图标（base64 PNG/JPEG，或 `data:` URL） |
| `setTitle` | 设置标题（支持多行、对齐） |
| `setState` | 切换动作状态 |
| `setSettings` / `getSettings` | 写入/读取动作设置 |
| `setGlobalSettings` / `getGlobalSettings` | 全局设置 |
| `showAlert` / `showOk` | 按键警示/确认动画 |
| `openUrl` | 打开网址 |
| `logMessage` | 写入客户端日志 |
| `switchToProfile` | 切换场景 |
| `sendToPropertyInspector` | 插件 → PI |
| `sendToDevice` / `webSendToDevice` / `webConnectDevice` | 设备级消息（推断：插件直连设备通道） |
| `downUrlFile` / `url` / `useDialog` | 下载文件/打开对话框（客户端扩展指令） |

消息统一格式（兼容 StreamDeck）：

```json
{ "event": "<指令>", "context": "<动作实例ID>", "action": "<动作UUID>", "payload": { } }
```

## 6. 属性检查器（Property Inspector）

- 由 `PropertyInspectorPath` 指定 HTML 页面，客户端以 WebView 打开；
- PI 通过 WebSocket 连接同一端口，注册事件 `registerPropertyInspector`；
- PI → 插件：`sendToPlugin`；插件 → PI：`sendToPropertyInspector`；
- PI 可调用 `setSettings` / `getSettings` / `setGlobalSettings` 读写配置；
- 调试页 `http://localhost:23519/` 可重载 PI。

---

## 7. 多动作与控制器

- `SupportedInMultiActions: true` 的动作可放入「多动作」容器；
- 多动作在 profile 中以 `children` 数组存储，每个子动作有 `Settings.delay`；
- `Controllers` 为空 = Keypad；含 `Encoder` = 旋钮动作（推断：`"Controllers": ["Encoder"]`）；
- `MultiActionImage` 用于多动作在画布上的图标。

---

## 8. Profile / 场景结构（与插件相关部分）

- 场景文件：`%APPDATA%\HotSpot\StreamDock\profiles\<UUID>.sdProfile`；
- 页面：`profiles/<PageUUID>.sdProfile`，含 `Actions` 映射（位置 → 动作）；
- 插件动作条目包含：`UUID`（动作 UUID）、`ActionID`（实例 ID）、`Settings`、`States`、`Controllers`；
- 插件自带场景通过 manifest `Profiles` 字段声明，安装时可导入；
- `DontAutoSwitchWhenInstalled` 控制安装后是否自动切换到插件场景。

---

## 9. 与 n4pro-core 复刻的对接点

要完整替代官方客户端，插件层需要实现：

1. **插件扫描器**：遍历 `%APPDATA%\HotSpot\StreamDock\plugins\*.sdPlugin`，解析 `manifest.json`，建立 `UUID → 动作定义` 索引；
2. **进程管理**：按 `CodePathWin` 启动 `node`/exe，传入 `-port/-pluginUUID/-registerEvent/-info`，维护进程生命周期与崩溃重启；
3. **WebSocket 服务**：本地监听端口，处理 `registerPlugin`/`registerPropertyInspector`，维护 `context → 动作实例` 映射；
4. **事件转发**：把物理按键/旋钮/触摸事件转换为 `keyDown`/`keyUp`/`dialRotate` 等发给对应动作的插件进程；
5. **指令处理**：接收 `setImage`/`setTitle`/`setState`/`showAlert` 等，转换为 HID 帧（复用现有渲染管线）；
6. **设置持久化**：`setSettings`/`getSettings` 写回 profile（注意：当前项目定位为**只读配置**，需要决策是否允许写回）；
7. **PI 宿主**：若复刻 GUI，需要 WebView2 承载 `PropertyInspectorPath`；
8. **调试页**：可选实现 `localhost:23519` 等价页面。
