## 2. 容器格式：AIC.FW

### 2.1 文件头（0x000–0x180）

```
00000000  41 49 43 2e 46 57 00 00 64 32 31 78  AIC.FW..d21x
00000048  64 65 6d 6f 38 38 5f 6e 6f 72        demo88_nor
00000080  31 2e 30 2e 30                      1.0.0
000000C8  73 70 69 2d 6e 6f 72                 spi-nor
```

| 偏移 | 字段 | 值 | 说明 |
|---|---|---|---|
| 0x000 | 魔数 | `AIC.FW\0\0` | Artinchip 固件容器 |
| 0x008 | SoC 代号 | `d21x` | Artinchip D21x 系列 |
| 0x048 | 板级名 | `demo88_nor` | SPI NOR 启动方案 |
| 0x080 | 容器版本 | `1.0.0` | |
| 0x0C8 | 存储介质 | `spi-nor` | |

### 2.2 头部偏移表（0x14C–0x158，小端 u32）

| 偏移 | 值 | 推断含义 |
|---|---|---|
| 0x14C | `0x00000800` | META 区起始 |
| 0x150 | `0x00001000` | 分区/镜像信息起始 |
| 0x154 | `0x00001800` | 第一个子镜像起始 |
| 0x158 | `0x00A31800` | 镜像有效尾部（文件大小 0xA33000 − 0x1800） |

### 2.3 META 区（0x800–0x1800）

字符串表显示 6 个元数据块：

| 偏移 | 内容 |
|---|---|
| 0x808 | `META … image.updater.ddr` |
| 0xA08 | `META … image.updater.spl` |
| 0xC08 | `META … image.info` |
| 0xE08 | `META … image.target.spl`，分区名 `spl` |
| 0x1008 | `META … image.target.env`，分区名 `env;env_r` |
| 0x1208 | `META … image.target.os`，分区名 `os` |

> 推断：META 区描述升级器（updater）与目标分区（target）的映射，供 `UpDateToolV3` 与 `aicupg` 选择写入位置。

### 2.4 AIC 子镜像头

三处 `AIC `（`41 49 43 20`）子头：

| 偏移 | CRC 字段 | 头部字段（抽样） |
|---|---|---|
| 0x1800 | `0x9D06EB65` | `01 00 01 00`、`0x6F10`、`0x6F00`、`0x6CE0`、`0x1D8`、`0x100`、`0x6BD0` |
| 0x8800 | `0x42A33D04` | `01 00 01 00`、`0x6F10`、`0x6F00`、`0x6CE0`、`0x1D8`、`0x100`、`0x6BD0`、`0x7000` |
| 0xF800 | `0x459B7DBA` | `01 00 01 00`、`0x28D10`、`0x289A8`、`0x28D00`、`0x28B00`、`0x1D8` |

> 观测：头部含 CRC32、版本 `1.0.1`、长度类字段与对齐值（0x1D8、0x100）。
> 推断：0x1800 为 SPL、0x8800 为 U-Boot/更新器、0xF800 为 OS 主镜像；具体字段语义未逐项验证。

## 3. 分区布局

### 3.1 从 FAL 分区表读出的官方布局（偏移 0xEF340）

```
spi0.0:512k(spl),128k(env),128k(env_r),2m(os),3m(rodata),9m(data)
```

| 分区 | 起始 | 大小 | 用途 |
|---|---|---|---|
| spl | 0x000000 | 512 KB | 一级引导（tinySPL） |
| env | 0x080000 | 128 KB | U-Boot 环境变量 |
| env_r | 0x0A0000 | 128 KB | 环境变量备份 |
| os | 0x0C0000 | 2 MB | RT-Thread 系统镜像 |
| rodata | 0x2C0000 | 3 MB | 资源/只读数据 |
| data | 0x5C0000 | 9 MB | 用户数据/图片缓存 |

> 观测：`RT-Thread Flash Abstraction Layer`、`fal_init`、`aic_get_fal_partition_table` 等字符串证实这是运行时真正使用的分区表。

### 3.2 img 包内实际内容

| 区间 | 长度 | 内容 |
|---|---|---|
| 0x000000–0x001800 | 6 KB | AIC.FW 头 + META |
| 0x001800–0x298000 | 2.59 MB | SPL + U-Boot + os（有效数据） |
| 0x298000–0xA33000 | 7.59 MB | **全部 0xFF 填充**（未包含） |

> 观测：0x298000 之后非零字节仅约 0.3%，且熵为 0（单一值 0xFF）。
> 结论：**升级包不包含 rodata（3 MB）与 data（9 MB）分区内容**。用户提到的“9 MB 资源区”不在本 img 内，而位于设备 flash 的 data 分区。

## 4. 处理器与运行时

| 项目 | 结论 | 证据 |
|---|---|---|
| 架构 | **RISC-V 64 位 + RVC 压缩指令** | capstone 反汇编成功；字符串 `ld-linux-riscv64xthead-lp64.so.1` |
| 厂商扩展 | T-Head（玄铁） | 同上 `xthead` |
| SoC | Artinchip D21x | 头部 `d21x` |
| 运行基址 | **VA = 文件偏移 + 0x40000000** | 数据段指针 `0x4008B7B0` 对应 file 0x8B7B0，该处可正常反汇编为函数体 |
| OS | **RT-Thread** | `RT-Thread shell commands:`、`tshell`、`finsh`、`rt_*` 组件字符串 |
| 文件系统 | littlefs / elm(FAT) / devfs | `packages/third-party/littlefs/lfs.c`、`fat_read_from_fatfs`、`dfs already init` |
| 引导链 | tinySPL → U-Boot → os | `tinySPL [Built on %s %s]`、`U-Boot 环境`、META 中的 `image.target.*` |
| 设备树 | FDT/DTB @ 0x69800 | `d0 0d fe ed` 魔数 |
| 升级器 | `aicupg`（hid/usb/uart 三种通道） | 见第 9 节 |

> 说明：本 img 的 0x1800–0x298000 区间同时包含 tinySPL/U-Boot 与 RT-Thread os 的代码与字符串，三段 AIC 子镜像按顺序排列。

## 5. 显示子系统

### 5.1 架构（观测）

显示不是 MCU 风格的 SPI 写屏，而是 Artinchip 的 **DE（Display Engine）+ framebuffer + RGB 面板**：

| 模块 | 关键字符串（偏移） |
|---|---|
| DE | `aic_de_wait_for_vsync`(0xF5E98)、`aic_de_get_alpha_config`(0xF5EE0)、`aic_de_update_alpha_config`(0xF5EF8) |
| 混合 | `layer %d doesn't support alpha blending`(0xF5D58)、`Layer %d doesn't support color key blending`(0xF5D90) |
| Framebuffer | `aicfb_probe`(0xF6618)、`aicfb_ioctl`(0xF6628)、`aicfb_update_layer`(0xF65C0)、`fb0 allocated at 0x%x`(0xF6320) |
| 面板 | `aic_find_panel`(0xF6708)、`panel-rgb`(0xF6718)、`find panel driver : %s`(0xF66E0) |
| 缩放 | `ge_config_scaler`(0xF9940)、`the min size of rgb is 4x4, when scaler enable`(0xF9570) |
| DMA | `Test DMA memcpy`(0xF2238)、`dmaengine_prep_dma_memcpy fail!`(0xF20E0) |
| 同步 | `DE wait vsync irq failed`(0xF5CD8) |
| 背光/PWM | `PWM Device`(0xF0060)、`pwm_set_tb`(0xF6D10)、`aic_pwm_irq`(0xF6CE0)、`Failed to set PWM clk`(0xF9BE0) |
| 色彩格式 | `format(%d) do not support %dx%d color block`(0xF6348) |

### 5.2 支持的像素格式（偏移 0x1178F8）

```
rgba4444  bgra4444  rgb565  bgr565  argb1555  abgr1555
rgba5551  bgra5551  rgb888  bgr888  nv12  nv21  yuv422
```

> 观测：仅说明驱动层支持这些格式，**没有证据**表明面板实际使用 RGB565，也没有发现 96×96 RGB565 资源块。

### 5.3 渲染能力（观测/推断）

- **透明层**：DE 支持 alpha blending 与 color key（按 layer 能力开关）。
- **缩放**：由 GE（Graphics Engine）硬件 scaler 完成，非软件最近邻/双线性；最小 4×4。
- **同步**：`aic_de_wait_for_vsync` 表明刷新以 vsync 为节拍。
- **局部刷新**：有 `aicfb_update_layer`，但未在字节层面证实“坐标对齐/局部刷新区域”约束。
- **SPI 写屏函数**：**未找到**。显示链路为内存 framebuffer → DE → RGB 面板，不存在 MCU 式 SPI LCD 写点函数。

## 8. USB / HID 协议描述

### 8.1 设备与配置描述符（偏移 0x1203D0）

```
12 01 00 02 00 00 00 40 48 55 08 10 02 00 01 02 03 01   Device
09 02 42 00 02 01 00 80 E1                              Config
09 04 00 00 02 03 00 00 00                              Interface 0
09 21 00 02 00 01 22 24 00                              HID (reportLen=36)
07 05 82 03 00 02 01                                    EP 0x82 IN  Interrupt 512B
07 05 03 03 00 04 01                                    EP 0x03 OUT Interrupt 1024B
09 04 01 00 01 03 01 01 00                              Interface 1 (boot keyboard)
09 21 00 02 00 01 22 5A 00                              HID (reportLen=90)
07 05 81 03 40 00 01                                    EP 0x81 IN  Interrupt 64B
```

| 字段 | 值 |
|---|---|
| VID / PID | **0x5548 / 0x1008** |
| bcdUSB / bcdDevice | 0x0200 / 0x0002 |
| 配置总长 | 66 字节，2 个接口，450 mA |
| 接口 0 | HID，厂商自定义，2 个端点 |
| 端点 OUT | `0x03`，Interrupt，**1024 字节** |
| 端点 IN | `0x82`，Interrupt，512 字节 |
| 接口 1 | HID boot keyboard，端点 `0x81` IN 64 字节 |

> 与 PC 端实测完全对应：OUT 报告 1024 字节 + ReportID = 1025；IN 读回 512 字节 + ReportID = 513。

### 8.2 厂商 HID 报告描述符（偏移 0x2F858，36 字节）

```
06 00 FF        Usage Page (0xFF00 厂商自定义)
09 01           Usage 1
A1 01           Collection (Application)
09 02           Usage 2
15 00 25 FF     Logical Min 0 / Max 255
75 08           Report Size 8
96 00 04        Report Count 1024
81 02           Input  (Data,Var,Abs)
09 03           Usage 3
15 00 25 FF     同上
75 08           Report Size 8
96 00 04        Report Count 1024
91 02           Output (Data,Var,Abs)
C0              End Collection
```

> 观测：描述符声明 **Input 1024 字节、Output 1024 字节**，无 Report ID 项（ReportID=0）。
> 与实测差异：设备实际回复的 IN 报告为 512 字节（513 含 ID），小于描述符声明的 1024；可能由端点 `wMaxPacketSize=512` 分段或固件短包实现。

## 9. 升级与调试命令（隐藏指令实锤）

以下命令字符串位于固件内，属于 tinySPL / U-Boot / aicupg 的命令表：

### 9.1 升级通道选择（偏移 0x3035D 附近）

```
aicupg usb 0
aicupg usb 0 userid
aicupg usb 0 force
aicupg hid 0
aicupg hid 0 userid
aicupg hid 0 force
aicupg uart 0
aicupg uart 0 userid
```

- `userid`：升级模式下的用户标识参数（**不是**“调试握手密钥”）。
- `force`：强制进入升级模式。
- 通道：USB、HID、UART 三选一。

### 9.2 内存与存储操作

| 命令 | 说明（固件内帮助文本） |
|---|---|
| `md [b/w/l] <addr> <count>` | 内存显示 |
| `mw` | 内存写 |
| `mtd list / dump / read / write / erase` | MTD 分区读写擦 |
| `mtd bypass <1/0>` | 绕过/启用 SPI 加密（`bypass spienc`） |
| `spinor init / dump / read / write / erase` | SPI NOR 直接操作 |
| `part init / list / dump` | 分区表操作 |
| `crc32 <addr> <length>` | 内存 CRC32 |
| `run <cmd> [args]` | 在升级流程中执行任意命令 |
| `fw_setenv` / `fw_printenv` | U-Boot 环境变量读写 |
| `ramboot` | 从 RAM 启动 |
| `env` | 环境变量读写（`bar_spinor_load_env_simple`） |

> 推断：“批量写显存”在原理上可借 `mw` 直接写 framebuffer 内存实现（DE 的 fb0 位于 RAM），但这需要 UART/升级模式权限，**不是** PC 客户端 HID 协议提供的命令。固件中未发现 HID 层的“批量写显存”指令。

### 9.3 显示/驱动自测命令

| 命令 | 说明 |
|---|---|
| `test_dma_memcpy` | DMA 内存拷贝测速 |
| `dma_dump` | 导出 DMA 寄存器 |
| `pwm_set_tb <ch> <freq>` | 设置 PWM 时基 |
| `pwm_status` | 查看 PWM 状态 |

> 背光：固件含完整 PWM 驱动与中断处理，**未找到** “backlight” 字符串或 0–100 级亮度映射表。推断背光由某个 PWM 通道控制，具体通道/极性需解析 FDT（0x69800）或实测。

## 12. 未完成项与后续建议

1. **获取 rodata/data 分区**：字体、图标、PC 协议版本表可能都在这些分区；可从设备 flash 读取（`spinor dump`）或从官方安装包中寻找含资源的镜像。
2. **完整反汇编 os**：本机无 Ghidra（REA 固件 provider 需 Linux binwalk/unblob），仅做了定向抽样反汇编；命令分派、背光控制、局部刷新仍需 Ghidra/IDA 完整分析。
3. **解析 FDT（0x69800）**：可得到 panel 时序、PWM 通道、framebuffer 地址与格式。
4. **UART 调试入口**：`Console UART ready` 表明有调试串口，需确认波特率与进入条件（可能需短接/按键组合）。
5. **HID 隐藏命令验证**：在确保安全的前提下，用设备端 UART 或升级模式验证 `mw` 写 framebuffer 的可行性与风险。
