# 01 · HID 通信协议（N4 Pro）

> 本文总结已通过实机帧日志与官方程序逆向确认的 HID 协议规则。
> 标注「推断」的条目未经过逐字节验证，接入新项目时需先做最小回环验证。

## 1. 设备标识

| 项目 | 值 |
|---|---|
| 厂商 ID (VID) | `0x5548` |
| 产品 ID (PID) | `0x1008` |
| 厂商集合 Usage Page | `0xFFA0` |
| 厂商集合 Usage | `1` |
| 键盘/鼠标集合 | 同一 VID/PID 的 `mi_00` / `mi_01` 子集合（打开失败属正常，忽略） |

枚举时会出现大量其它 HID 设备（键鼠等），逐个 `CreateFile` 会返回错误码 2（找不到文件），属正常探测行为。

## 2. 报告长度与打开方式

| 方向 | 长度 | 说明 |
|---|---|---|
| 输出（主机→设备） | **1025 字节** | `ReportID(1) + 载荷(1024)` |
| 输入（设备→主机） | **513 字节** | 第 1 字节为 ReportID，解析时跳过 |

- 必须用 `CreateFileW` 打开厂商集合路径（`\\?\hid#vid_5548&pid_1008...`）。
- 推荐 `FILE_FLAG_OVERLAPPED` + 两个事件对象，实现单句柄重叠读写，读阻塞不影响写。
- 每次写必须一次写入完整 1025 字节；不要拆分 USB 传输。

## 3. 输出帧通用结构

```
偏移(帧)  长度  内容
0         1     ReportID = 0x00
1         3     ASCII "CRT"
4         2     0x00 0x00
6         8     命令字符串（不足补 0，如 "BAT"、"BGPIC"）
14...     剩余  命令参数
```

- 1024 字节载荷内，命令位于载荷偏移 5（即帧偏移 6）。
- 命令名最长 8 字节。

## 4. 命令字典

### 4.1 控制类

| 命令 | 参数 | 作用 |
|---|---|---|
| `DIS` | 无 | 清屏/断开当前画面（初始化第一条） |
| `LIG` | 载荷[10] = 亮度 0~100 | 设置整体亮度 |
| `LBLIG` | 载荷[10] = 亮度 0~100 | 设置标签/灯带亮度 |
| `QUCMD` | 载荷[10]=0x1F、[11]=0x11、[13]=0x11、[15]=0x11 | 查询/握手（实测序列） |
| `CLE` | 载荷[11] = 0xFF（普通清层） | 清空图层 |
| `BGCLE` | 载荷[10] = 模式 | 清空背景层 |
| `SETLB` | 无 | 提交标签层 |
| `STP` | 无 | 提交/停止当前帧组（刷新收尾） |
| `CONNECT` | 无 | 连接/会话宣告 |
| `RGBS` | 无 | 心跳，建议 2 秒一次 |

### 4.2 图像类

#### BGPIC（触摸条 / 背景图）

```
载荷[10]      = 0x00
载荷[11..13]  = PNG 总长度，24 位大端（((len>>16)&0xFF, (len>>8)&0xFF, len&0xFF)）
载荷[18..19]  = 宽度，16 位大端（800 = 0x03 0x20）
载荷[20..21]  = 高度，16 位大端（130 = 0x00 0x82）
载荷[22]      = 0x00
载荷[23]      = 0xFF
之后按 1024 字节分片，每片一帧，不再带任何头
```

- Control Bar 与触摸条背景统一使用 **800×130** 单视口图。
- 官方 `updateN4ProTouchBarBackground` 固定使用 0x320 / 0x82 常量（800 / 130）。

#### BAT（按键 / 触摸条分区图）

```
载荷[10..11] = PNG 总长度，16 位大端（上限 0xFFFF）
载荷[12]     = 图像索引
之后按 1024 字节分片
```

- 图像槽位与输入序号**不是**简单 +5，必须按物理行映射：
  - 上排按键（输入 1~5）→ 槽位 **11~15**
  - 下排按键（输入 6~10）→ 槽位 **6~10**
  - 触摸条旋钮分区 → 槽位 **1~4**
  - 槽位 **5** 未使用（空槽）
- 触摸条在按键模式下按 4 个分区发送，使用同一 BAT 索引空间（实现中占用 1~4 区）。
- 单张图建议 < 64 KB，PNG 编码后分片发送。

### 4.3 退出帧

官方 `SDDevice::closeHidDevice` → `sendDisconnectCommand`，在 `hid_close` 之前发送：

```
CRT + "CLE"，载荷[11]='D'(0x44)，载荷[12]='C'(0x43)
```

即 `CLE` + 参数 `"DC"`。作用：通知固件结束会话、复位显示状态。
**不发送该帧直接退出，会让设备停在异常状态（USB 异常 / 需重新插拔）。**

## 5. 标准时序

### 5.1 启动

```
DIS
LIG(brightness)
CLE
触摸条分区 BAT × 4
按键 BAT × 10
SETLB
STP
CONNECT
（之后每 2 秒 RGBS 心跳）
```

实测整页刷新约 177~385 帧（取决于 PNG 大小与页面图片数量）。

### 5.2 整页刷新（切页 / 重连）

```
CLE → 触摸条图 → 10 键 BAT → SETLB → STP
```

- 顺序不能颠倒：先清层，再逐层提交，最后 STP。
- `BGPIC/BGCLE` 会覆盖按键层，只在 Control Bar 背景场景使用。

### 5.3 局部刷新

| 场景 | 序列 |
|---|---|
| 单键图像 | 该键 `BAT` + `SETLB` + `STP`（实现中可批量合并） |
| 触摸条滑动 | 仅一个 `BGPIC`（800×130），约 60ms 节流 |
| 模式切换 | 仅触摸条区域重发（旋钮 33~98 帧，Control Bar 98 帧左右） |

## 6. 输入报文

输入帧首字节为 ReportID，解析时跳过；有效内容从帧偏移 1 开始。

### 6.1 按键

```
00 41 43 4B 00 00 4F 4B 00 00 idx state ...
   A  C  K        O  K
```

- `idx`：1~10，物理按键序号（上排左起 1~5，下排左起 6~10）。
- `state`：`1` = 按下，`0` = 抬起。
- 按下时不需要重绘按键图。

### 6.2 触摸条

```
00 41 43 4B 00 41 52 58 ... x(BE16) y(BE16) ...
   A  C  K     A  R  X
```

- `ARX` 为触摸坐标报文；实现中固定提取 16 位大端 x、y。
- 滑动时会连续上报，按 30~60ms 节流刷新触摸条即可跟手。

### 6.3 模式切换

| 编码 | 含义 |
|---|---|
| `0xB1` | 切换到旋钮模式 |
| `0xB2` | 切换到 Control Bar 模式 |

### 6.4 旋钮旋转（实测编码）

| 旋钮 | 逆时针 | 顺时针 |
|---|---|---|
| 1 | `0xA0` | `0xA1` |
| 2 | `0x50` | `0x51` |
| 3 | `0x90` | `0x91` |
| 4 | `0x70` | `0x71` |

- 低 1 位为方向；实现中统一归一化为 `+1`（奇数码）/ `-1`（偶数码）。
- 每格上报一次，无加速度。

### 6.5 旋钮按下

| 编码 | 旋钮 | 状态 |
|---|---|---|
| `0x37` | 1 | state=1 按下 / 0 抬起 |
| `0x35` | 2 | 同上 |
| `0x33` | 3 | 同上 |
| `0x36` | 4 | 同上 |

### 6.6 Control Bar 点击

| 编码 | 含义 |
|---|---|
| `0x39` | 返回/左箭头 |
| `0x40`~`0x43` | 条目标签，附带 X 坐标（16 位大端，载荷偏移 11~12） |

## 7. 图像格式与方向

| 项目 | 规则 |
|---|---|
| 格式 | PNG（原始字节直发，不做二次封装） |
| 按键尺寸 | 112×112 |
| 触摸条尺寸 | 800×130 |
| 旋转 | 发送前统一旋转 **180°**（按键与触摸条均需，否则真机上下颠倒） |
| 缩放 | 等比完整放入目标框并居中；小图放大、大图缩小、不裁剪（详见 04 文档） |

## 8. 异常与重连

| 现象 | 处理 |
|---|---|
| `CreateFile` 失败 | 进入 USB 等待模式，不退出进程 |
| 读错误 `1167`（设备未连接）/ `1784` | 关闭句柄、结束会话、进入等待模式 |
| 写错误 | 记录日志，短暂退避后重试 |
| 设备重新出现 | 重新打开 → `DIS/LIG/整页刷新/CONNECT` |

- 等待实现：隐藏窗口 + `RegisterDeviceNotificationW(WM_DEVICECHANGE)` 阻塞消息循环 + 2 秒兜底探测，CPU 占用接近 0。
- 断开时**不要**继续写图像帧，否则会拖慢重连。

## 9. 已知限制

- 设备偶发从系统消失（官方软件同样出现），多与线材/USB 口/供电有关；软件层只能等待重连。
- 进程被任务管理器强杀时无法发送 `CLE+DC`，设备可能停在异常态。
- 退出帧必须在关闭句柄前发出，且应等待其写入完成（建议 100~250ms）。
